# 부가가치세 신고 자료 (일반과세자)

## Why

사용자는 홈택스 부가가치세 신고 화면(일반과세자)을 옆에 열어 두고 숫자를 칸 번호 순서대로 옮겨 적는다. 지금은 세금계산서 목록과 카드 매입 목록(`/exports`)만 있어서, 사용자가 직접 칸별로 나눠 더해야 한다. 이 기능은 승인된 매입·매출 전표에서 신고서와 부속서류의 칸을 채워 보여 주고 같은 모양의 Excel을 준다. 원천세 화면(`/payroll/withholding`)과 같은 성격이다. 참고 화면일 뿐 전자신고 파일은 만들지 않는다. 사용자는 개발자 한 명이고 실제 회사는 아직 없으며, 홈택스 제출로 검증할 수 없다.

- 신용카드매출전표등 수령명세서(갑): 별지 제16호서식(1) `<개정 2019. 3. 20.>`. https://www.law.go.kr/LSW/flDownload.do?flSeq=162619767
- 매출처별 세금계산서합계표(갑): 별지 제38호서식(1) `<개정 2024. 3. 22.>`. https://www.law.go.kr/LSW/flDownload.do?flSeq=162619955
- 매입처별 세금계산서합계표(갑): 별지 제39호서식(1) `<개정 2024. 3. 22.>`. https://www.law.go.kr/LSW/flDownload.do?flSeq=162619965

- 신고기간: 부가가치세법 제5조, 제48조, 제49조. 시행령 제90조(예정고지, 1억5천만원 기준).
- 전자신고세액공제: 조세특례제한법 제104조의8, 시행령 제104조의5④. 대통령령 제36127호(2026. 2. 27.)가 1만원을 **5,000원**으로 바꿨다. 확정신고에만 적용되며, 매출과 매입이 모두 없는 일반과세자는 받지 못한다.

**확인하지 못한 것:** 홈택스 전자신고 화면의 실제 문구와 입력 순서. 화면에서는 서식의 칸 번호와 이름을 쓰고, 홈택스 화면과 맞는다는 표현을 쓰지 않는다.

**주의:** 현재 서식에는 (11) 수출기업 수입분 납부유예가 있다. 그래서 그 밖의 공제매입세액이 (15), 공제받지 못할 매입세액이 (17)이며, 명세는 제4쪽에 있다. 예전 서식의 (14)/(16)과 다르다.

## Decision

### 신고 구분과 기간

- 화면에서 연도, 기(1기·2기), 구분(예정·확정)을 고른다. URL은 `year`, `term`(1|2), `kind`(prelim|final)이다. 기본값은 오늘 이전에 끝난 가장 최근 신고기간이다.
- **예정:** 1–3월(1기), 7–9월(2기).
- **확정:** URL `prelim`(1|0)은 "이 기의 예정신고를 했다"는 뜻이다.
  - 1이면 확정은 남은 석 달(4–6월, 10–12월)이다.
  - 0이면 여섯 달 전체(1–6월, 7–12월)이다.
  - 기본값: 법인(`company.businessType = 'corporation'`)은 1, 개인은 0.
  - 이유: 개인과 직전 기 공급가액 1억5천만원 미만 법인은 예정신고 대신 예정고지를 받고 확정에서 여섯 달을 신고하는데, 이 프로그램은 직전 기 공급가액 기준을 판단하지 않는다. 그래서 사용자가 고르게 한다(제 판단).
- 날짜는 전표 `date` 기준이다.
- 대상은 승인된 전표만이다(`POSTED_STATUSES`). `entry_type`은 `purchase` / `sale`만 쓴다.
- 수정·취소분(음수 머리)은 부호 그대로 더한다.

### 전표 → 신고서 칸 (제1쪽)

금액은 머리 `supply_amount`의 합이고 세액은 `vat_amount`의 합이다. 서식은 (1)–(4) 세액을 금액 × 10/100으로 적게 하지만, 우리는 세금계산서·영수증에 실제로 찍힌 세액의 합을 쓴다. 둘이 1원이라도 다르면 해당 칸 아래에 "금액 × 10%와 N원 차이"를 표시한다(제 판단).

**매출 (`entry_type = 'sale'`):**

| 칸 | 조건 |
|---|---|
| (1) 과세 세금계산서 발급분 | `vat_type = taxable`, 증빙 `tax_invoice` |
| (2) 과세 매입자발행 세금계산서 | 계산하지 않음 |
| (3) 과세 신용카드ㆍ현금영수증 발행분 | `taxable`, 증빙 `card` / `cash_receipt` |
| (4) 과세 기타(정규영수증 외 매출분) | `taxable`, 그 밖의 증빙 |
| (5) 영세율 세금계산서 발급분 | `zero_rated`, `tax_invoice` |
| (6) 영세율 기타 | `zero_rated`, 그 밖의 증빙 |
| (7) 예정신고 누락분, (8) 대손세액 가감 | 계산하지 않음 |
| (9) 합계 = ㉮ | (1)–(8)의 합 |

면세 매출(`exempt`)은 제4쪽 면세사업 수입금액 (88) 합계 금액에 들어간다. 그중 증빙이 `invoice`인 것은 (89) 계산서 발급금액에도 들어간다.

**매입 (`entry_type = 'purchase'`):**

고정자산 판정: 매입 전표의 **주 계정**(간이 빌더의 비용·자산 줄, `toSimpleInput`이 돌려주는 주 계정)이 `noncurrent_asset` 그룹이면 고정자산, 아니면 일반이다. 매입 전표에는 주 계정 줄, 부가세 줄, 상대 계정 줄(미지급금·현금 등)이 있으므로 "부가세가 아닌 줄"로 고르면 안 된다. 상대 계정이 비유동자산인 매입(예: 주 계정은 비용, 상대는 보증금)도 일반으로 나와야 한다. 이 경우를 테스트로 고정한다.

| 칸 | 조건 |
|---|---|
| (10) 세금계산서 수취분 일반매입 | 증빙 `tax_invoice`, 일반. 공제 여부와 상관없이 모두 넣는다(영세율 포함) |
| (11) 수출기업 수입분 납부유예 | 계산하지 않음 |
| (12) 세금계산서 수취분 고정자산매입 | 증빙 `tax_invoice`, 고정자산. 공제 여부와 상관없이 모두 |
| (13) 예정신고 누락분, (14) 매입자발행 세금계산서 | 계산하지 않음 |
| (15) 그 밖의 공제매입세액 | 제4쪽 (52) 합계 |
| (16) 합계 | (10)-(11)+(12)+(13)+(14)+(15), 서식대로 (11)을 뺀다 |
| (17) 공제받지 못할 매입세액 | 제4쪽 (56) 합계 |
| (18) 차감계 = ㉯ | (16)-(17) |

간이영수증, 증빙 없음, 계산서 매입은 신고서 매입세액에 넣지 않는다. 계산서 매입(`invoice`)은 제4쪽 (90) 계산서 수취금액에 넣는다.

**세액 계산:**

| 칸 | 값 |
|---|---|
| 납부(환급)세액 ㉰ | ㉮-㉯ |
| (19) 그 밖의 경감ㆍ공제세액 | 제4쪽 (63) |
| (20) 신용카드매출전표등 발행공제 등 | 계산하지 않음(일부 개인 업종만 해당) |
| (21) 합계 = ㉱ | (19)+(20) |
| (22) 소규모 개인사업자 감면세액 | 계산하지 않음 |
| (23) 예정신고 미환급세액 | URL `prelimRefund`(0 이상 정수원, 기본 0). 확정에서만 입력칸을 보인다 |
| (24) 예정고지세액 | URL `notice`(같은 규칙). 확정에서만 보인다 |
| (25)–(28) | 계산하지 않음 |
| (29) 가산세액 계 | 계산하지 않음 |
| (30) 차감ㆍ가감하여 납부할 세액(환급받을 세액) | ㉰-㉱-㉲-㉳-㉴-㉵-㉶-㉷-㉸+㉹. 계산하지 않는 칸은 0으로 둔다 |

(30) 옆에는 "계산하지 않은 칸은 0으로 보고 계산했습니다"를 표시한다. 음수이면 환급받을 세액으로 표시한다. 잘못된 `prelimRefund` / `notice` 값은 0으로 보고 입력칸에 오류를 표시한다(원천세 `refund`와 같은 방식).

**과세표준명세 (31)–(35):** 회사에 업태·종목 정보가 없다. 그래서 (35) 합계 = (9) 금액만 채우고, (31)–(34)는 "업태·종목별로 직접 나눠 적으세요"로 표시한다.

### 제4쪽 명세

- **(15) 그 밖의 공제매입세액 명세:**
  - (44) 신용카드매출전표등 수령명세서 제출분 일반매입, (45) 같은 제출분 고정자산매입: 증빙 `card` / `cash_receipt`이고 `vat_type = taxable`이고 `vat_deductible = true`인 매입이다. 고정자산 판정은 위와 같다.
  - (46)–(51)은 계산하지 않는다. (52) = (44)–(51)의 합이다.
- **(17) 공제받지 못할 매입세액 명세:**
  - (53): 증빙 `tax_invoice`이고 `vat_deductible = false`인 매입이다.
  - (54), (55)는 계산하지 않는다. (56)은 합계다.
  - 제22호서식의 사유별 명세(①–⑨)는 전표에 사유가 없어서 만들지 않는다. "사유별 명세는 직접 나눠 적으세요"로 표시한다.
- **(19) 그 밖의 경감ㆍ공제세액 명세:**
  - (57) 전자신고 세액공제: 확정이고 이 기간에 대상 매출 또는 매입 전표가 한 건이라도 있으면 5,000원을 넣는다. 예정이면 0이다.
  - URL `efile=0`이면 0이다(세무대리인이 신고하는 경우 등). 기본은 1이다.
  - 화면에 근거(조특법 시행령 제104조의5④, 2026. 2. 27. 이후 전자신고)를 적는다.
  - 금액은 `src/lib/vat/` 상수 하나에 출처 주석과 함께 둔다(제 판단). 급여처럼 시점별 표로 만들지 않는다.
  - (58)–(62)는 계산하지 않는다. (63)은 합계다.
- **예정신고 누락분 명세 (36)–(43)과 가산세 명세 (64)–(84):** 행 이름과 "이 프로그램에서 계산하지 않음"만 보인다.
- **면세사업 수입금액:** (88) 합계만 채운다. (85)–(87)은 계산하지 않음으로 둔다.
- **계산서 명세:** (89), (90)을 채운다.

### 새 전표 필드 두 개

- `vouchers.paper_tax_invoice boolean`
  - 매입·매출 폼에 `종이 세금계산서` 스위치로 보인다. 증빙이 세금계산서일 때만 보이고, 기본은 꺼짐이다.
  - 켜면 이 세금계산서는 "과세기간 종료일 다음 달 11일까지 전송된 전자세금계산서 외" 분으로 본다.
- `vouchers.unregistered_card boolean`
  - 매입 폼에 `홈택스 미등록 카드` 스위치로 보인다. 증빙이 신용카드일 때만 보이고, 기본은 꺼짐이다.
  - 켜면 수령명세서의 ⑧ 그 밖의 신용카드 등으로 본다.
- 공통 규칙:
  - 두 필드는 증빙이 맞지 않으면 null이다. DB check로 강제한다.
  - 불러오기(홈택스 세금계산서·카드 파일)로 만든 전표는 둘 다 false다.
  - 폼에서 바꾸는 것은 막지 않는다.
  - 다른 머리 필드처럼 `voucher_history` 스냅숏과 간이 빌더 입력(`SimpleInput`)에 들어가서 재검증(`toSimpleInput` → `buildSimpleVoucher` → `sameVoucher`)이 그대로 동작해야 한다.
  - 거래 템플릿에는 저장하지 않는다. 템플릿을 적용하면 꺼짐이다(제 판단).
  - 수정·취소분 스위치와 함께 쓸 수 있다.

### 부속서류

같은 화면 아래 탭(또는 구역)과 Excel 시트로 보인다.

**매출처별 세금계산서합계표(갑), 매입처별 세금계산서합계표(갑):**
- 대상: 기간 안의 증빙 `tax_invoice` 매출 / 매입 전표다. 공제 여부와 상관없이 넣고, 계산서(`invoice`)는 넣지 않는다.
- **총합계 표:** 행은 합계, 전자 발급분(사업자등록번호 / 주민등록번호 / 소계), 전자 외 발급분(같은 세 줄)이다. 열은 매출처수(매입처수), 매수, 공급가액, 세액이다.
  - 전자 외 = `paper_tax_invoice = true`
  - 사업자등록번호 발급분 = 거래처에 사업자등록번호(10자리)가 있는 건
  - 주민등록번호 발급분 = 그 밖의 건
  - 처수 = 고유 사업자등록번호 수. 번호가 없는 건은 거래처 id로 센다.
- **전자 외 발급분 처별 명세:** 사업자등록번호 발급분만, 사업자등록번호별로 묶는다. 열은 번호, 사업자등록번호, 상호, 매수, 공급가액, 세액이다.
  - 수정·취소분도 매수와 금액에 더한다(서식 작성방법).
  - 화면에는 행 수 제한이 없다. 갑 서식이 5행이므로 "6번째부터는 (을) 서식"이라는 안내만 둔다.
- 상호와 사업자등록번호는 불러오기 메타가 있으면 메타를, 없으면 거래처를 쓴다. 기존 `listTaxInvoices`와 같은 규칙이다.

**신용카드매출전표등 수령명세서(갑):**
- 대상: 증빙 `card` / `cash_receipt`이고 `vat_type = taxable`이고 `vat_deductible = true`인 매입이다. 서식대로 세금계산서를 받은 거래와 사업무관 거래는 넣지 않는다.
- **합계 표:** 행은 ④합계, ⑤현금영수증, ⑥화물운전자복지카드(계산하지 않음, 0), ⑦사업용 신용카드(`card`이고 `unregistered_card = false`), ⑧그 밖의 신용카드 등(`card`이고 `unregistered_card = true`)이다. 열은 거래건수, 공급가액, 세액이다.
- **⑧ 명세:** (카드회원번호, 가맹점 사업자등록번호)별로 묶는다. 열은 일련번호, 카드회원번호, 가맹점 사업자등록번호, 거래건수, 공급가액, 세액이다.
  - 카드번호는 불러오기 메타 `cardNo`를 쓰고, 없으면 "직접 입력"으로 표시한다.
  - 갑 서식이 15행이므로 넘으면 (을) 안내를 둔다.
- ④ 합계는 신고서 (44)+(45)와 같아야 한다. 테스트로 고정한다.

### 화면, Excel, 권한

- **경로:** `/exports/vat-return`. 사이드바 `세무사 자료` 아래 `부가세 신고 자료`로 넣는다(`src/lib/nav.ts`, 스모크 테스트 대상). 권한은 `export:tax`다.
- **급여 전표:** `entry_type`이 매입·매출이 아니므로 섞이지 않는다.
- **화면 구성:**
  - 위: 기간 선택, `prelim` 선택, `efile` 선택, 확정일 때 (23)/(24) 입력칸.
  - 이어서 기간과 대상 전표 건수를 보인다.
  - 그 아래 제1쪽 표(칸 번호 | 이름 | 금액 | 세율 | 세액), 제4쪽 명세, 부속서류 세 개.
  - 서식에서 음영인 칸은 비워 둔다. 계산하지 않는 칸은 `이 프로그램에서 계산하지 않음`(원천세의 `NOT_COMPUTED_TEXT`를 함께 쓴다)으로 표시한다.
  - 위쪽 안내문: "홈택스 전자신고 화면의 문구·순서는 확인하지 않았습니다. 서식(2026. 3. 20. 개정)의 칸 번호를 따릅니다."
- **Excel:** `GET /api/exports/vat-return`이 같은 URL 파라미터를 받는다. exceljs로 만든다.
  - 시트: `신고서`, `매출처별 합계표`, `매입처별 합계표`, `신용카드 수령명세서`
  - 파일명: `부가세신고자료_{year}_{term}기_{예정|확정}.xlsx`
- **빈 기간:** 대상 전표가 없으면 표는 0으로 보이고 "이 기간에 승인된 매입·매출 전표가 없습니다."를 표시한다. 이때 (57)은 0이다.
- **구조:**
  - 순수 빌더는 `src/lib/vat/`에 둔다. 행 정의, 기간 계산, 칸 집계는 전표 요약 배열을 받아 결과를 돌려준다.
  - 로더는 `src/server/vat/`에 둔다. 승인 전표, 거래처, 불러오기 메타, 비부가세 줄의 계정 그룹을 읽는다.
  - 원천세(`src/lib/withholding/`, `src/server/withholding/`)와 같은 나눔이다.

## Non-goals

- 홈택스 전자신고 파일(변환 파일) 생성
- 간이과세자 신고서, 영세율 조기환급 신고, 기한후 신고, 수정신고
- 공제받지 못할 매입세액의 사유별 명세(제22호서식), 공통매입세액 안분
- 의제매입세액, 재활용폐자원, 대손세액, 가산세 계산
- 업태·종목별 과세표준명세(회사 정보에 업태·종목을 추가하지 않는다)
- 매입자발행 세금계산서, 계산서합계표, 현금매출명세서, 부동산임대공급가액명세서 등 다른 부속서류
- 사업장별(총괄납부·사업자단위) 나눔. 회사 하나를 한 사업장으로 본다
- 직전 기 공급가액으로 예정고지 대상 여부를 판정하는 기능

## Anti-goals

- 홈택스에서 검증됐다고 말하는 문구
- 계산하지 않은 칸을 계산한 것처럼 보이게 하는 표시. 0과 "계산하지 않음"을 구분한다.
- 서식과 다른 칸 번호
